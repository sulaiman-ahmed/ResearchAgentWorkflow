# mini-benchling-agents

> **Work in progress — Phase A complete.** Built incrementally, one ticket at a time.
> A full README with demo instructions, architecture overview, evaluation results, and limitations will be written at [Issue #29](https://github.com/sulaiman-ahmed/ResearchAgentWorkflow/issues/29) once the implementation is complete and verified.

A local macOS application demonstrating three connected lab-informatics workflows:

1. **CSV Import** — upload a measurement file, review an AI-proposed column mapping, approve it, and persist validated measurements with full source provenance.
2. **Historical Check** — create an experiment and receive an automated comparison against historical records.
3. **Research** — submit a research question, retrieve evidence through generated MCP connectors, and save a cited notebook draft.

---

## Stack

| Layer | Choice |
|---|---|
| Backend | Python 3.12, FastAPI, Pydantic, SQLAlchemy, Alembic |
| Database | PostgreSQL 17 (JSONB for flexible fields) |
| Jobs | PostgreSQL row-locking — no Redis |
| Frontend | React + TypeScript + Vite *(not yet built)* |
| AI/Models | Fake deterministic provider for tests; one live provider adapter *(not yet built)* |
| MCP Connectors | FastMCP, generated from OpenAPI specs *(not yet built)* |
| Runtime | Docker Desktop / Rancher Desktop + Compose on macOS |

## What exists now (Phase A)

### Running services

```bash
docker compose up -d --wait db
docker compose up -d api
curl http://127.0.0.1:8000/health   # {"status":"ok"}
curl http://127.0.0.1:8000/ready    # {"status":"ok","model_mode":"fake"}
```

### Package structure

```
src/minibench/
  main.py          # FastAPI app — /health, /ready
  settings.py      # Pydantic-settings config
  db.py            # Async SQLAlchemy engine + session factory
  api/             # Route modules (empty stubs)
  domain/          # Schemas, ORM models, services (empty stubs)
  runtime/         # Worker, executor, repository (empty stubs)
  agents/          # Agent handlers (empty stubs)
  llm/             # Model adapters (empty stubs)
  connectors/      # MCP connector generator (empty stubs)
  scripts/         # seed_demo, evaluate (empty stubs)
migrations/        # Alembic (no migrations yet — added in Issue #5)
tests/unit|integration|e2e|live/
fixtures/          # Synthetic CSV inputs + expected JSON outputs
```

### Fixtures

Six CSV test files and their expected outputs, generated by `fixtures/generate.py`:

| File | Shape |
|---|---|
| `clean.csv` | 20 valid rows, canonical headers |
| `renamed_headers.csv` | Same 20 rows — headers need AI mapping |
| `unknown_sample.csv` | 20 valid + 1 unresolvable sample ID |
| `ambiguous_alias.csv` | 20 valid + 1 alias matching two samples |
| `bad_unit.csv` | 20 valid + 1 unsupported unit |
| `malformed.csv` | Unclosed quote — file-level parse failure |

Also: `experiments.json` (20 historical), `samples.json` (30), `molecules.json` (5), and two historical-check case files.

Regenerate at any time (idempotent):

```bash
uv run python fixtures/generate.py
```

### CI

GitHub Actions runs on every push to `main`: locked dependency install → Ruff lint + format check → Alembic migrations → pytest.

## Prerequisites

- macOS (Apple silicon or Intel), zsh
- [Rancher Desktop](https://rancherdesktop.io/) or [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) running
- [uv](https://docs.astral.sh/uv/) — Python toolchain manager
- Node 24 (for the frontend, added in Issue #12)

```bash
uv python install 3.12
uv sync --locked
```
